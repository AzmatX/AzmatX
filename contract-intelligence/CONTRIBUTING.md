# Contributing Guidelines

## Workflow
1. Branch from `develop` using the agreed feature naming.
2. Keep pull requests focused and small.
3. Run lint, tests, and build validation before creating a PR.
4. Request review from at least one teammate.

## Commit Convention
Use clear, task-based commit messages:
- `feat(ocr): add document preprocessor`
- `fix(risk): handle empty clause predictions`
- `test(api): add health endpoint tests`

## Pull Request Checklist
- [ ] Linked issue
- [ ] Unit tests added/updated
- [ ] Lint and tests passed
- [ ] Documentation updated if needed
